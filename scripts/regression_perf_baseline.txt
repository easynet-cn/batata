# Performance anchors for `scripts/regression.sh --perf`
#
# Format:
#   <machine_id>|<storage>|<mode>|<case>|<median_rps>|<cv_pct>|<captured>|<bench_params>
#
#   machine_id   `perf_machine_id()`: lowercased `sysctl -n hw.model` with
#                punctuation stripped, plus the core count, e.g.
#                `macbookpro161-16t`. Override with PERF_MACHINE_ID (CI).
#                A machine with no rows is never compared against someone
#                else's numbers: the stage reports "no anchors" and stops.
#   storage      rocks | mysql | postgres
#   mode         standalone | cluster
#   case         the scenario label printed by scripts/benchmark.sh
#   cv_pct       observed spread (max-min)/median * 100 over the captured
#                rounds. Used as this machine's tolerance floor.
#   bench_params c<connections>-t<threads>-w<workers>-d<duration>-r<rounds>,
#                so a number captured with different load settings is visibly
#                not comparable.
#
# Absolute RPS only means something on the box that produced it. Anchors are
# therefore keyed by machine: a new workstation starts with an empty file and
# you record its own epoch with
#
#   ./scripts/regression.sh --perf-capture            # rocks / standalone
#   PERF_ROUNDS=5 PERF_STORAGE=mysql ./scripts/regression.sh --perf-capture
#
# Tolerance is max(cv_pct, PERF_TOLERANCE), never a single global number: a
# box that cannot resolve better than 40% must not fail runs for a 20% drop.
#
# The perf stage is advisory by default - it is the only stage whose result
# depends on how busy the host is. Pass --perf-gate to make a drop block.
#
# Historical (frozen) anchors for MacBookPro16,1 / i9-9880H: see
# scripts/regression_perf_history.txt.
